## 2. 背景知识

### 2.1 内存地图与"怪癖"是模拟器的第一课

GBA 的地址空间不是一块均匀的内存，而是几个宽度不同的设备挂在固定窗口上：

| 区域 | 起点 | 大小 | 总线宽 |
|------|------|------|--------|
| BIOS | 0x00000000 | 16 KiB | 16 位 |
| EWRAM | 0x02000000 | 256 KiB | 16 位 |
| IWRAM | 0x03000000 | 32 KiB | 32 位 |
| I/O | 0x04000000 | 1 KiB | — |
| 调色板 | 0x05000000 | 1 KiB | 16 位 |
| VRAM | 0x06000000 | 96 KiB | 16 位 |
| OAM | 0x07000000 | 1 KiB | 32 位 |
| ROM | 0x08000000 | ≤32 MiB | 16 位 |
| 存档 | 0x0E000000 | ≤64 KiB | **8 位** |

三个最具教学价值的怪癖（`bus.rs` 里各有一个测试锁住）：

1. **镜像**：区域实际容量不足窗口大小时低位回卷。访问 `0x02040000` 命中
   EWRAM 的 `0x000000`——实现只需一行 `相对地址 & (容量-1)`。注意 ROM 的
   镜像算法：`(地址 - 0x08000000) & 0x01FFFFFF`，所以 `0x0A000008` 读到
   `ROM[8]`，但 `0x09000008` 读的是窗口内偏移 `0x01000008`（另一个位置！）。
   我第一版测试就在这里想当然，被自己的测试教育了。
2. **VRAM/调色板的 8 位写**：16 位总线收到 8 位数据，物理上两个字节通道
   都得到这个值——于是背景区 8 位写会把字节复制进整个半字。但**精灵区
   （0x06010000 起）是普通单字节写**。漏掉这个规则的游戏会花屏。
3. **OAM 忽略 8 位写；SRAM 宽读字节重复**：32 位设备的 8 位写不生效；
   8 位设备的 16/32 位读让同一字节出现在每个字节通道上
   （`read_u32(0x0E000000)` = `0x5A5A5A5A`）。总线宽度决定行为，没有例外。

### 2.2 寄存器银行：异常处理的第一道防线

ARM7TDMI 有 7 种运行模式（CPSR 低 5 位）。关键设计：**异常模式有自己
私有的 r13/r14**（FIQ 还私有 r8–r12）。进入 IRQ 时硬件自动"换银行"，
中断处理程序用私有的 SP/LR，不会踩坏游戏正用着的寄存器。

```
              r0-r7      r8-r12     r13/r14        SPSR
User/System   共用       共用       银行 0         无
FIQ           共用       ★私有      银行 1         有
IRQ           共用       共用       银行 2         有
Supervisor    共用       共用       银行 3         有
Abort/Und     共用       共用       银行 4/5       有
```

实现技巧（`Cpu::switch_mode`）：FIQ 的 r8–r12 用 `swap_with_slice` 整体
互换——因为只有 FIQ 一个模式私有它们，"换入 = 换出"恰好是一对。

### 2.3 流水线与 PC：模拟器最著名的约定

ARM 的三级流水线意味着执行第 N 条指令时，第 N+2 条已经在取指。所以
**读 R15 得到"当前指令地址 + 8"（ARM 态）/ + 4（Thumb 态）**。

本项目把这个事实做成了硬约定：

```text
执行指令期间：regs[15] = 当前指令地址 + 8（ARM）
取指地址    = regs[15] - 8
普通指令执行完：regs[15] += 4（推进流水线）
分支落地时   ：regs[15] = 目标地址 + 8（维持约定！）
```

为什么分支写的是"目标 + 8"而不是"目标"？因为下一条要执行的是目标指令，
而约定要求**执行它时** `regs[15]` 已经指向"它 + 8"。这个设计让所有
"读 PC"的指令（`LDR r0, [r15]`、分支偏移计算）零调整直读 `regs[15]`。

由此还派生两个架构怪癖，都写进了注释：
- `BL` 的返回地址是"本指令 + 4"而不是 +8——硬件特意为流水线多减了 4；
- `STR` 存 PC 时存的是"本指令 + 12"，比读 PC 还多 4（GBATEK 原文如此）。

### 2.4 桶形移位器的进位：一张必须背下的表

ARM 的数据指令格式是 `操作 目的, 操作数1, 操作数2[+移位]`。当指令带
`S` 标志时，逻辑类操作（AND/EOR/MOV…）的 C 来自**移位器**，算术类
（ADD/SUB…）的 C 来自**运算器**——两条通路，别搞混。

| 移位 | 编码量 0 的含义 | C 的来源 |
|------|-----------------|----------|
| LSL  | 不移位（C 不变）| 移出位 = 原值位 (32-n) |
| LSR  | **移 32 位**    | 原值位 (n-1)；n=32 时 = 位 31 |
| ASR  | **移 32 位**    | 同上（n≥32 时 = 符号位）|
| ROR  | **RRX**（带 C 右移 1 位）| n%32==0 时 = 位 31 |

"编码 0 = 32"只对**立即数**编码成立；寄存器指定移位量时 0 就是不移。
`alu.rs` 把两种入口拆成 `shift_imm` / `shift_reg` 两个函数，
让类型系统替我们记住区别。

### 2.5 手工汇编：读懂集成测试的程序

`gba.rs` 集成测试的求和程序，逐字解码（全部 32 位，位 31–28 是条件码）：

```text
E3A02402 = MOV r2, #0x02000000
  E      cond=AL
   3     I=1（立即数）op1=001
    A    op=1101（MOV）
     02402 → S=0, Rn=0, Rd=2, rot=4, imm=0x02
  值 = 0x02 ROR (4×2=8) = 0x02000000  ← 32 位立即数要"旋转"编码：
     8 位立即数 + 4 位旋转量能表示一大类数，这正是 ARM 立即数的精妙处

E4821004 = STR r1, [r2], #4
  E4     I=0 P=0（后索引：先用 Rn 原值访问，再把偏移加回 Rn）
   8     U=1（偏移向上）
    2    B=0 W=0（半字不涉及；后索引的 W 位另有含义）
     1   L=0（存储）
      004 → Rn=r2, Rd=r1, 偏移=4

1AFFFFFB = BNE -5 条
  1      cond=NE（Z=0 才跳）
   A     101 + L=0 → B
    FFFFFB → 24 位补码 = -5，目标 = 本指令+8 + (-5×4) = 0x0800000C
```

我第一次写 BNE 偏移时算成 -4（跳到了 STR 而不是 ADD），测试立刻抓出来了
——手工汇编是检验译码器最好的陪练。

## 3. 代码走读

### 3.1 总线分发：一个 match 就是整个地图

`Bus::read_u8` 的 `match addr >> 24` 就是内存地图的代码化。所有宽度
（u8/u16/u32）都从 u8 读写复合而来，镜像通过掩码自然获得。16/32 位
访问会先强制对齐（`addr & !1` / `& !3`）——CPU 侧的"非对齐旋转"是
指令层的语义（`single_transfer` 里 `rotate_right((addr & 3) * 8)`），
总线层只管对齐，两层职责不混。

### 3.2 指令分发：两级 match

```text
arm_step → 检查条件码 → execute（按位 27–25 分 8 类）
         → category_000 里再细辨 BX / 乘法 / SWP / 数据处理
```

两个容易踩的编码陷阱（都已在代码注释里标明）：
- `MRS`/`MSR` 潜伏在"比较类指令 + S=0"的非法编码空间，必须**先于**
  普通数据处理识别，掩码 `0x0FBF0FFF == 0x010F0000` 等直接取自 GBATEK；
- 位 7、4 同时为 1 的编码同时被乘法、SWP、半字传输三类共享，
  靠位 24（乘法=0）与完整掩码区分。

### 3.3 错误策略：未实现 ≠ 未定义

`CpuError::Unimplemented`（返回 `Err`）只用于**开发期还没写的合法指令**——
撞上就大声报错，绝不静默；而协处理器指令触发**未定义指令异常**（进入
Und 模式、跳向量 0x04）——那是真机的真实行为，属于模拟而非错误。
两条路径语义完全不同，未来 ArmWrestler 跑起来时，前者指向我们的 TODO，
后者指向游戏的 bug。

### 3.4 调试实录：8 个失败测试的验尸报告

第一次跑测试 8 个失败，逐一定位后分成两类——**这个分类本身就是方法论**：

| 失败 | 根因 | 类别 |
|------|------|------|
| `movs_sets_carry` | 指令编码 `0xE1B01008` 的移位字段半字节错位（LSL #1 应为 `0xE1B01080`），译码成了"MOVS r1, r8" | 测试错 |
| `umull` 结果 hi=0xFFFFFFFF | 编码少了 U 位（`0xE0854291` 是 SMULL！U=1 应为 `0xE0C54291`），-1×2 的符号扩展恰好"像"错的结果 | 测试错 |
| `conditional_execution` | 逻辑写反：Z=0 时 MOVNE **应该**执行；且 `MOVS r0,#0` 会破坏 r0（改用 r5） | 测试错 |
| `adds` 断言 Z | 0xFFFFFFFF+2=1，结果非 0，Z 本来就该是 0——期望值没算 | 测试错 |
| 集成测试 BNE | 分支偏移 -4 算成跳到 STR，正确是 -5（目标 = ADD） | 测试错 |
| 集成测试 r2 | 后索引推进 5 次是 0+20=0x14，我写成 0x18 | 测试错 |
| 镜像测试 | `0x09000008` 的窗口内偏移是 0x01000008（超出 16 位小 ROM），我误以为是镜像 | 测试错 |
| **SRAM 宽读** | 宽读的字节重复必须显式实现——逐字节复合读不到"总线宽度"效应 | **真 bug** |
| **启动 SP** | 银行副本 ≠ 可见寄存器，`new_no_bios` 忘了把 `banked_sp[0]` 装进 `regs[13]` | **真 bug** |

经验：**期望值要手工演算**（就像 00 篇演算校验和那样）， failing test 先
怀疑自己的测试再怀疑实现；但真 bug 往往藏在"边界语义"（总线宽度、初始
状态一致性）而不是主逻辑里。

## 5. 下一步预告：M1 第二步

- **`LDM`/`STM`**（块传输）：一次搬运多个寄存器，含 S 位（用户态银行
  强制访问）与 PC 装载（异常返回）两个特殊语义——函数序言/尾声全靠它；
- **`SWP` 与半字/有符号传输**（`LDRH`/`STRH`/`LDRSB`/`LDRSH`）；
- **Thumb 全部 19 种指令格式**：GBA 游戏代码以 Thumb 为主（16 位指令在
  16 位 ROM 总线上效率更高），做完它就能尝试跑 ArmWrestler 了。
